# Google Ads Copy Frameworks

Use this reference when writing or reviewing Google RSA, Demand Gen, PMax, YouTube, or landing-page message angles.

## RSA Limits

| Component | Recommended | Limit |
| --- | ---: | ---: |
| Headlines | 8-15 | 30 characters each |
| Descriptions | 3-4 | 90 characters each |
| Display paths | 1-2 | 15 characters each |

## Frameworks

### AIDA

Use for broad search intent and cold traffic.

- Headline pattern: `[Keyword/Need] + [Benefit]`
- Description pattern: `[Problem or desire]. [Specific benefit]. [CTA].`

### PAS

Use for problem-aware searches and lead generation.

- Headline pattern: `[Problem] Solved`
- Description pattern: `[Problem]. [Consequence]. [Solution/offer]. [CTA].`

### 4P

Use for premium or high-ticket services.

- Promise: outcome the user wants.
- Picture: what success looks like.
- Proof: review, number, certification, case, or differentiator.
- Push: clear next action.

### FAB

Use for technical services, ecommerce, and comparison intent.

- Feature: what it is.
- Advantage: why it is better.
- Benefit: why the user should care.

## Medical and Sensitive Copy

Before final copy for medical, healthcare, cosmetic clinic, pharmacy, supplements, finance, legal, housing, employment, addiction, or minors-related offers:

- Read `medical-policy-check.md` where relevant.
- Avoid guaranteed outcomes, shame/fear language, before-after promises, sensitive personal attributes, and unsupported superiority claims.
- Prefer factual service language, eligibility criteria, process clarity, doctor/provider credentials, and consultation CTAs.

## Review Checklist

For every ad group or asset group:

- Keyword or search intent appears naturally in at least some headlines.
- Offer, proof, and CTA are clear.
- Descriptions explain why the user should act now without misleading urgency.
- Final URL and landing-page H1 match the promise.
- Duplicate headlines across ad groups are avoided unless intentionally shared.
- Claims can be verified on the landing page.
